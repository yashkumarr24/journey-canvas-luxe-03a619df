# Project architecture rules

- Use numbered additive DB migrations; preserve catalogue sync and data.
- Buttons wrap and grow; phone target/focus CSS excludes native offline controls, preserving recovery and auth.
- Keep search editors mounted. Catalogue RPCs are FastAPI-only; branch exact selections before joins with a live (region_id, tj_hotel_id) index to bound city paging. Listing retains per-hotel batch context.
- Hotel Book/Details/Confirm/Cancel live in backend services/hotel_booking.py with compare-and-set status transitions on hotel_bookings (0018); prevents duplicate provider bookings and keeps provider handles server-side.
- Instant hotel booking and hold confirmation are refused in production until server-side payment verification exists; they debit the TripJack wallet.
- Holiday packages (0019) are enquiry-only catalogue tables with indicative prices and no booking/payment fields; writes go through FastAPI service_role, clients read published rows only, so packages can never be booked or charged directly.
- Package import keeps one package per source DOCX and only flags possible duplicates (code/name/destination) in package_duplicate_candidates (0020); merging needs human review so no source content is lost.
- Package DOCX importer (backend/app/package_import, CLI app.diagnostics.package_import) is dry-run by default, capped at 5 files per run and international-only in the current phase, writes only with --execute --confirm IMPORT-PACKAGES, inserts unpublished, creates no package without a matched destination, uploads images to the private package-images bucket (package_images.url = storage:// ref, served later via signed URLs because public buckets are blocked), and flags gaps as needs_review.
- Package importer runs a coverage pass (backend/app/package_import/coverage.py) after extraction: every body, text-box, table, header/footer and footnote line is either stored or reported verbatim as unclassified with source context in review_text.csv, plus a per-file extraction_summary.csv; this guarantees no source content is silently dropped across varied DOCX layouts.
- Keep assistant validation, automatic flight/hotel queries, result shaping, and booking handoffs in the shared assistant-search controller so the header workspace and dedicated assistant page cannot diverge.
- Domestic Word-file packages live as static source data in src/data/domestic-packages.ts under /domestic-packages/* routes and share the domestic destination grid with the existing catalogue; keeps older destination routes untouched and options isolated per source quotation.
- International /international-packages/* groups countries with legacy aliases and full trips. Shared frontend search indexes all catalogues separately; validated place queries filter whole trips, preserving content and provider isolation.
- International photography uses an explicit included-stop selection for trips and exact city matching for destination cards, backed by licensed stock photos; this prevents unrelated country fallback photography.
- Package photos bundle licensed originals (domestic WebP, international JPG); Lovable-relative assets fail cross-host. Shrink package grid children and scroll source tables locally; never clip page overflow.
- Browser server-function bearer attach uses src/lib/auth/bearer-middleware.ts (null-safe @/lib/supabase/client) and never the generated @/integrations/supabase/client, which throws when VITE_SUPABASE_* is absent and would break public server functions (e.g. the enquiry form) on hosts like Vercel; missing config means "no token", never a failed request.
- Payments use PayU Hosted Checkout through FastAPI only (services/payments.py, payment_fulfilment.py, migrations 0023-0024): capture needs reverse hash plus server verify_payment and runs in the payu_capture DB function that also enqueues one durable fulfilment job; jobs never re-send Book once a booking left DRAFT, refunds need admin, booking reconciliation and a locked balance check, and everything is gated by PAYMENTS_ENABLED/PAYMENT_FULFILMENT_ENABLED with PayU test only against TripJack UAT; the browser only auto-posts server-signed fields and deployed sites never simulate payments. Payment modules never import hotel_booking/flight_booking/bookings repo/TripJack code (protected, VPS-local fixes); the live hotel port is uninstalled so jobs are never claimed, flight orders are refused, and a refund needs a failed_confirmed job or an atomically withdrawn never-claimed job with the hotel still DRAFT.
- Capacitor loads the canonical site with native-only imports, preserving web/SSR. Google uses the system browser/App Links; assetlinks JSON needs a direct public response (apex too). iOS awaits signing IDs. Splash auto-hides natively; startup/Retry are bounded, not normal navigation/OAuth. MainActivity preserves BridgeWebViewClient but handles main-frame errors; OfflineNavigation handles client route failures, never images/background fetches. Fallback/recovery clear only navigation history; offline Back exits, preserving sessions and excluding raw error entries.
