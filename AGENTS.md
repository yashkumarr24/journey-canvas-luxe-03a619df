# Project architecture rules

- Optional pre-book Fare Validate is excluded; Flight Booking candidates use server-owned Review evidence and pure documented request builders with unconditional execution refusal until separately authorized, preventing unfinished validation or paid/held bookings from shipping.

- Flight Review resolves the selected fare's stored plural price references, retains provider bookingId privately and conditions in the existing session snapshot, and gates all FAREALERT/amount changes on existing consent; map literal documented condition booleans to separate passport, PAN, document-ID and per-pax DOB requirements, preserving unknown fields without aliases or geography inference so distinct documents cannot be conflated; never construct multi-city combinations.

- Normalize flight fare-rule response wrappers and dynamic route policy topics in the booking API client before Review rendering; keeps provider response shape out of the UI without changing other API contracts.

- Flight Seat Map (backend app/services/flight_seatmap.py) is read-only and optional: the provider bookingId comes only from the owned review session, TripJack is called only when stored Review conditions.isa is literally true, and tripSeatMap seats/flags/amounts pass through verbatim with availability derived solely from isBooked=false; no DB writes, no Book/payment changes.

- Use numbered additive DB migrations; preserve catalogue sync and data.
- Flight customer booking items and HTTP details use nested display allowlists; keep raw Review evidence in private sessions/contexts and fix applied capture migrations forward-only, preventing owner/guest/provider-handle disclosure.
- Buttons wrap and grow; phone target/focus CSS excludes native offline controls, preserving recovery and auth.
- Hotel filter scrollports stay viewport-bounded and opt out of Lenis wheel handling so every filter is reachable without scrolling the results.
- Keep search editors mounted. Catalogue RPCs are FastAPI-only with indexed selections. Listing uses paced process-wide bounded workers, full-request deadlines and per-hotel context; incomplete searches stay explicit. Large hotel searches are progressive: an initial window answers, a same-pacing background task delivers the rest via the polled progress endpoint; partial never shows as complete.
- Hotel Book/Details/Confirm/Cancel live in backend services/hotel_booking.py with compare-and-set status transitions on hotel_bookings (0018); prevents duplicate provider bookings and keeps provider handles server-side.
- Hotel guest capture requires a durable bookings parent and hotel_bookings link created by one service-role RPC; no memory fallback or awaiting_payment on persistence failure, so checkout always has a stable parent identity.
- VPS Hotel payment candidates must preserve payments.booking_id -> bookings and applied Flight migrations; quarantine unapproved SQL outside runner inputs and reconcile deployed payment code before release, because branch migration files are not a live schema ledger.
- Staging Hotel/PayU proposals keep parent-only payment linkage and shared reference rules unchanged, derive subject kind from the parent booking type and authorize guests through the private linked Hotel row; candidate migrations and code patches stay outside active execution paths until separately reviewed, preventing production or Flight drift.
- Instant hotel booking and hold confirmation are refused in production until server-side payment verification exists; they debit the TripJack wallet.
- Holiday packages (0019) are enquiry-only catalogue tables with indicative prices and no booking/payment fields; writes go through FastAPI service_role, clients read published rows only, so packages can never be booked or charged.
- Package import keeps one package per source DOCX and only flags possible duplicates (code/name/destination) in package_duplicate_candidates (0020); merging needs human review so no source content is lost.
- Package DOCX importer (backend/app/package_import, CLI app.diagnostics.package_import) is dry-run by default, capped at 5 files per run and international-only in the current phase, writes only with --execute --confirm IMPORT-PACKAGES, inserts unpublished, creates no package without a matched destination, uploads images to the private package-images bucket (package_images.url = storage:// ref, served later via signed URLs because public buckets are blocked), and flags gaps as needs_review.
- Package importer runs a coverage pass (backend/app/package_import/coverage.py) after extraction: every body, text-box, table, header/footer and footnote line is stored or reported verbatim as unclassified in review_text.csv plus a per-file extraction_summary.csv, so no source content is silently dropped across varied DOCX layouts.
- Keep assistant validation, automatic flight/hotel queries, result shaping, and booking handoffs in the shared assistant-search controller so the header workspace and dedicated assistant page cannot diverge.
- Domestic Word-file packages live as static source data in src/data/domestic-packages.ts under /domestic-packages/* routes and share the domestic destination grid; keeps older destination routes untouched and options isolated per source quotation.
- International /international-packages/* groups countries with legacy aliases and full trips. Shared frontend search indexes all catalogues separately; validated place queries filter whole trips, preserving content and provider isolation.
- International photography uses an explicit included-stop selection for trips and exact city matching for destination cards, backed by licensed stock photos, preventing unrelated country fallback photography.
- Package photos bundle licensed originals (domestic WebP, international JPG); Lovable-relative assets fail cross-host. Shrink package grid children and scroll source tables locally; never clip page overflow.
- Browser bearer attach uses src/lib/auth/bearer-middleware.ts (null-safe @/lib/supabase/client), never the generated @/integrations/supabase/client, which throws when VITE_SUPABASE_* is absent and would break public server functions on hosts like Vercel; missing config means "no token", never a failed request.
- Payments use PayU Hosted Checkout through FastAPI only: capture requires reverse hash plus server verification and atomic job enqueue. The VPS-only Hotel adapter validates captured database evidence through payments.hotel_booking_id (not a bookings parent), identity/reference/owner/amount/currency before entering the unchanged loaded Hotel lifecycle; UAT/test settings, or production PayU plus the confirmed production Hotel pair, Hotel key and the default-off Hotel production flag, permit execution via a server-built verified-payment proof (instant only; browser routes, holds and hold confirmation stay refused), and uncertain/reclaimed attempts never rebook. Checkout's linked-draft RPC remains a separate prerequisite. Flight orders remain refused and Flight/payment modules unchanged; refunds retain reconciliation and locked-balance requirements.
- Capacitor loads the canonical site with native-only imports, preserving web/SSR. Google uses the system browser/App Links; assetlinks JSON needs a direct public response (apex too). iOS awaits signing IDs. Splash auto-hides natively; startup/Retry are bounded, not normal navigation/OAuth. MainActivity preserves BridgeWebViewClient but handles main-frame errors; OfflineNavigation handles client route failures, never images/background fetches. Fallback/recovery clear only navigation history; offline Back exits, preserving sessions and excluding raw error entries.
- Hotel HMS and OMS hosts must classify as one environment: UAT (apitest*.tripjack.com, existing UAT key) or production (exact surface allowlists: UAT key for apitest-hms/apitest-hotel-booker, TRIPJACK_HOTEL_API_KEY for hms-search/hms-booker); mixed/unlisted/non-HTTPS leaves Hotels unconfigured ; Book/Confirm run only on UAT until verified PayU reaches them, Cancel runs on any consistent pair, so keys never cross environments and guessed hosts never get live traffic.
